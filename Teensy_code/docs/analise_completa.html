⚠️ Avisos e Pontos de Atenção

ALTO Lógica de Fallback de Encoders Sem Documentação
A função traveledTicks() usa um algoritmo de seleção de encoder que pode ser confuso
// RobotControl.cpp linha 529-547 int32_t RobotControl::traveledTicks(const PlannerInput& in) const { const int32_t deltaFl = in.encFlTicks - _startFlTicks; const int32_t deltaRr = in.encRrTicks - _startRrTicks; const int32_t dfl = abs(deltaFl); const int32_t drr = abs(deltaRr); if (diff > ERROR_THRESHOLD || direcao) { if (dfl > drr) { return dfl; // Usa só o encoder FL se tiver muita diferença } else { return drr; // Usa só o encoder RR } } else{ return (dfl + drr) / 2; // Média se forem parecidos } }
Impacto: Funciona, mas a lógica precisa ser validada em campo. Se um encoder falhar, o robô pode se desviar. O threshold de 150 ticks pode precisar ser calibrado.
MÉDIO Convenção de Nomenclatura Inconsistente
A classe se chama "motor" (minúscula) em vez de "Motor" (maiúscula)
// Motor.h linha 5: class motor { // Deveria ser: class Motor // Uso em main.cpp linha 31-34: motor mFL(Ain1_M3, Ain2_M3); motor mRL(Ain1_M4, Ain2_M4); motor mFR(Ain1_M1, Ain2_M1); motor mRR(Ain1_M2, Ain2_M2);
Impacto: Não afeta funcionalidade, mas viola convenções C++ (PascalCase para classes). Dificulta legibilidade e manutenção futura.
MÉDIO Possível Problema de Compatibilidade I2C
Múltiplos dispositivos I2C podem ter conflitos de addressing
// config.h linha 154-158: constexpr uint8_t TCA_A = 0x70; // Multiplexador A constexpr uint8_t TCA_B = 0x71; // Multiplexador B constexpr uint8_t OPENMVL = 0x12; // Câmera esquerda constexpr uint8_t OPENMVR = 0x13; // Câmera direita constexpr uint8_t BNO055_ADDRESS = 0x28; // IMU // Setup() inicializa em ordem: 1. BNO055 2. ToF 3. Encoder/Bumper (não I2C) 4. Cameras (comentado)
Impacto: Se os TCA9548A multiplexadores não estiverem bem inicializados antes dos ToF, pode haver conflitos. Recomenda-se testar inicialização com i2c_scanner.
